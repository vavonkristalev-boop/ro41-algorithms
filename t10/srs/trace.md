# Лабораторная работа — Трассировка сортировок и поиска (t10)

## 1. Сортировка выбором (Selection Sort)
Исходный массив: a = {5, 2, 9, 1, 7} (размер N = 5)

Ищем минимальный элемент в неотсортированной части и меняем его местами с текущим элементом под индексом i.
Количество сравнений на каждом проходе всегда равно числу оставшихся элементов минус 1 (то есть N - 1 - i).

* Проход i=0: ищем минимум среди всех {5, 2, 9, 1, 7}. Минимум равен 1 (индекс 3). Меняем местами 5 и 1. Массив стал: {1, 2, 9, 5, 7}. Сравнений сделано: 4.
* Проход i=1: ищем минимум среди {2, 9, 5, 7}. Минимум равен 2 (индекс 1). Он уже на своем месте, обмен не нужен. Массив остался: {1, 2, 9, 5, 7}. Сравнений сделано: 3.
* Проход i=2: ищем минимум среди {9, 5, 7}. Минимум равен 5 (индекс 3). Меняем местами 9 и 5. Массив стал: {1, 2, 5, 9, 7}. Сравнений сделано: 2.
* Проход i=3: ищем минимум среди {9, 7}. Минимум равен 7 (индекс 4). Меняем местами 9 и 7. Массив стал: {1, 2, 5, 7, 9}. Сравнений сделано: 1.

Общее число сравнений: 4 + 3 + 2 + 1 = 10 сравнений.

## 2. Сортировка вставками (Insertion Sort)
Исходный массив: a = {4, 3, 2, 1}

Берем элемент (key) и двигаем его влево, сдвигая большие элементы вправо, пока не найдем правильное место.

* Шаг i=1: key = 3. Двигаем влево. Сдвигов: 1. Массив после вставки: {3, 4, 2, 1}
* Шаг i=2: key = 2. Двигаем влево мимо 4 и 3. Сдвигов: 2. Массив после вставки: {2, 3, 4, 1}
* Шаг i=3: key = 1. Двигаем влево через все элементы. Сдвигов: 3. Массив после вставки: {1, 2, 3, 4}

Всего сдвигов: 1 + 2 + 3 = 6 сдвигов.

Ответ на дополнительный вопрос:
На уже отсортированном массиве из 4 элементов алгоритм сделает ровно 3 сравнения (по одному сравнению на каждом шаге i от 1 до 3, чтобы просто проверить, что элемент уже стоит правильно и сдвигать ничего не нужно).

## 3. Бинарный поиск (Binary Search)
Массив: {1, 3, 5, 7, 9, 11, 13} (индексы от 0 до 6)

### Трассировка для x = 7:
* Шаг 1: lo = 0, hi = 6. Считаем mid = (0 + 6) / 2 = 3. Смотрим элемент a[3] = 7. Значение найдено! Поиск завершен успешно. Решение: возвращаем индекс 3.

### Трассировка для x = 6 (ищем элемент, которого нет):
* Шаг 1: lo = 0, hi = 6. mid = (0 + 6) / 2 = 3. Элемент a[3] = 7. Так как 6 < 7, смещаем правую границу: hi = mid - 1 = 2.
* Шаг 2: lo = 0, hi = 2. mid = (0 + 2) / 2 = 1. Элемент a[1] = 3. Так как 6 > 3, смещаем левую границу: lo = mid + 1 = 2.
* Шаг 3: lo = 2, hi = 2. mid = (2 + 2) / 2 = 2. Элемент a[2] = 5. Так как 6 > 5, смещаем левую границу: lo = mid + 1 = 3.

Чем закончится поиск для x = 6:
Цикл остановится, так как lo (3) стало больше hi (2). Обычный бинарный поиск вернет -1 (элемент не найден).

Что вернет метод LowerBound(6):
Метод LowerBound ищет индекс первого элемента, который больше или равен числу x. В данном случае поиск завершится на lo = 3. Элемент под индексом 3 — это число 7 (а 7 >= 6). Поэтому LowerBound(6) вернет индекс 3.
